# QuickBite Definition of Done

## 1. Overview

The Definition of Done establishes the conditions that each Product Backlog Item must meet before our team considers it completed.

Our goal is to make sure that every completed feature is functional, tested, reviewed, and properly integrated into the QuickBite application.

## 2. Definition of Done Checklist

A Product Backlog Item is considered Done when:

- [ ] The feature meets its acceptance criteria.
- [ ] The functionality has been implemented.
- [ ] The code has been committed to our shared GitHub repository.
- [ ] A pull request has been created and reviewed by another team member.
- [ ] Relevant tests have been performed successfully.
- [ ] The feature has been integrated into the main application.
- [ ] No known critical bugs remain.
- [ ] Any necessary documentation has been updated.
- [ ] The feature can be demonstrated successfully.

## 3. Applying the Definition of Done

Our team will use this checklist throughout the Sprint.

When a developer finishes implementing a feature, it will move to the In Review column on our GitHub Projects board.

Once the feature satisfies all the conditions in our Definition of Done, it can be moved to the Done column.

If any required condition is not met, the feature will remain unfinished until the issue is resolved.
